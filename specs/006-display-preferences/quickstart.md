# Quickstart: Verifying Display Preferences

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-23

This project has **no test suite** — the constitution's Verification Standard prohibits one.
Verification is: the compiler is clean, and a person exercises the change in the running
application. This file is that run.

---

## Prerequisites

- A MIDI source that can send notes, control changes, and a program change. A software keyboard
  (MidiKeys on macOS, loopMIDI plus any sender on Windows) is enough.
- The feature's own send screen works too: publish a source, target it, and send from the
  `Send` mode. That makes the run self-contained on either platform.

## Gates — all must pass before the manual run

```bash
cargo clippy --workspace --all-targets   # zero warnings; warnings are errors here
cargo fmt --check
npx tsc --noEmit                         # strict, zero errors
```

Then confirm no test artifacts were introduced — no `tests/` directory, no `#[cfg(test)]` added,
no `*.test.ts`, no test dependency in `Cargo.toml` or `package.json`.

Then confirm `src/bindings.ts` was **regenerated by the build**, not hand-edited: it must still
carry the generator's header, and the two new commands must appear in it.

## Launch

```bash
npm run tauri dev
```

## What has already been verified without the app

The rendering rules and the persistence rules were checked programmatically during
implementation, using a scratch crate held **outside the repository** so that no test artifact
was introduced (Verification Standard). Those results do not replace the run below — nothing
here has seen the actual window — but they mean the scenarios can concentrate on what only a
person at the screen can judge: layout, fidelity, and whether the thing feels right.

Already confirmed, 42 checks passing:

- **FR-029 / FR-030** — a document with no `display` key loads and takes the defaults; a
  document with one unrecognised display value (`"time": "sundial"`) loads with that field
  defaulted, the other five intact, and `retention: 4242` untouched. This was the sharpest risk
  in the feature, and it is the one Scenario 8 steps 5–6 exist to catch.
- **FR-015 / FR-016 / SC-004** — note 60 reads `C3` and `C4` under the two conventions, note 0
  reads `C-2`, note 127 reads `G8`, and all 128 numbers render under all four formats with no
  blanks.
- **FR-017 / FR-018 / SC-004** — controller 7 is `Volume (MSB)`, controller 64 is `Sustain`,
  controller 85 falls back to `85`, and all 128 render under all three formats with no blanks.
- **FR-020** — wire 0 reads `1` or `0`; wire 127 reads `128`.
- **FR-021** — changing the note format leaves the velocity alone, and vice versa.
- **FR-022 / FR-023** — a velocity-zero note reads `Note Off`, then `Note On` under `Expert
  mode`; a real `Note Off` stays one; running status keeps the decoded interpretation; Expert
  mode shows raw values and unticking restores the five choices exactly.
- **FR-013 / FR-014** — the four time formats, with the three host forms consistent conversions
  of one reading, and no `u64` wrap at a huge tick count.
- **Edge cases** — a 2000-byte SysEx still reports `2002 bytes` under `Hexadecimal number`
  rather than dumping; `Clock` carries no data.

## What was then verified in the running application

The scenarios below were afterwards driven for real on Windows, against the `goRave Virtual`
loopback port, which the app both monitors as a source and sends to as a destination — so it
feeds itself and no second program is needed. Screenshots were compared against
`screenshots/setting.jpg`, `data.png`, and `sources.png`.

- **Scenario 1** — the `Display` tab reproduces the reference: five groups, verbatim labels
  including the en dash in `1 – 128 (Standard)`, the checkbox, the three explanatory lines, and
  the reference defaults. The `Monitor` screen is unchanged against `data.png` and `sources.png`.
- **Scenario 2 / FR-025** — a retained `Note On` reading `C3 100` re-rendered to `C3 64` on
  switching `Data format` to hexadecimal. Same row, same timestamp, not re-received. The note
  stayed `C3` rather than becoming `3C`, which is FR-021 holding.
- **Scenario 5 / FR-025a** — a row captured while `Clock time` was selected showed
  `2053963412883` once `Host time (integer)` was chosen, and `205396.341288300` under
  `Host time (seconds)`. Those differ by exactly 10,000,000, this machine's performance-counter
  frequency, so FR-014 holds to the digit.
- **Scenario 6 / FR-022, FR-023, FR-027** — a `Note On` with velocity zero listed as `Note Off`,
  then as `Note On` with raw values the moment `Expert mode` was ticked, on the already-retained
  row. Unticking restored `Note Off` and `C3` with the five choices intact. The row count did not
  change either way, so no display setting moved an event past a filter.
- **Scenario 7** — `Sources` and `Other` are selectable, state that they are not available, and
  offer no operable control.
- **Scenario 8 / FR-028** — a choice survived a full quit and relaunch, and the stored document
  kept its filters, columns, retention, and the whole send half.

**Two defects were found this way and fixed**: the selected preferences tab had no visual
selected state at all, and the Time column truncated host readings to an ellipsis. Both are
recorded where they were fixed — `src/index.css` and `src/components/EventTable.tsx`.

**Still unverified by anything: all macOS code.** `midi-macos` is `#![cfg(target_os = "macos")]`,
so the crate is compiled out entirely on Windows and never type-checked there. The per-packet
timestamp threading in its `source.rs`, and with it the whole `HostTime::ZeroMeaningNow` path
that the third `Expert mode` line describes, needs a macOS build before it is trusted. Windows
never produces that variant, so nothing above exercises it.

## Scenario 1 — The tab reproduces the reference image (FR-008 … FR-012, SC-003)

Open the `Settings` mode and put `screenshots/setting.jpg` beside the window.

Check, character for character:

- Three tabs, in order: `Display`, `Sources`, `Other`. `Display` selected.
- Five group labels: `Time format`, `Note format`, `Controller format`, `Data format`,
  `Program number` with `(Decimal)` on a second line.
- Every option label verbatim — including the parentheses in `Note (Middle C = C3)` and the
  **en dash** in `1 – 128 (Standard)` and `0 – 127 (Less common)`. A hyphen here is a failure.
- Radios are radios and the checkbox is a checkbox. No segmented controls, no switches.
- Defaults: `Clock time`, `Note (Middle C = C3)`, `Standard name`, `Decimal number`,
  `1 – 128 (Standard)`, `Expert mode` unticked.
- The three lines beneath `Expert mode`, verbatim, bulleted and indented.
- Nothing extra: no Apply button, no Reset, no search, no icons.

Then open the `Monitor` mode and compare against `screenshots/data.png`, `filters.png`, and
`sources.png`: every control unchanged in label, type, order, and default (FR-007).

> **Expected deviation.** Note names now render one octave lower than `screenshots/data.png`
> shows, because the default is `Note (Middle C = C3)` per FR-011a. This is the recorded conflict
> in [plan.md](./plan.md) Complexity Tracking, not a defect. Selecting `Note (Middle C = C4)`
> restores the old naming.

## Scenario 2 — Retained events re-render (User Story 1, FR-025, FR-026, SC-002)

1. In `Monitor`, capture a few dozen events, then **pause**.
2. Note the top row's `Data` value and the list's scroll position.
3. Switch to `Settings`, select `Hexadecimal number` under `Data format`.
4. Return to `Monitor`.

Expect: the same rows, same order, same count, same scroll position, still paused — with
hexadecimal values. Within a second, no flicker, no reload.

5. Switch back to `Decimal number`. The original values return.

## Scenario 3 — The monitor keeps running (User Story 2, FR-002, FR-003, SC-005)

1. With traffic arriving and the monitor **not** paused, note the newest event id.
2. Set filters, hide a column, change the retention limit, deselect a source.
3. Visit `Settings`, wait several seconds, return.

Expect: events that arrived while away are present and none are duplicated or missing; filters,
columns, retention, and source selection are exactly as set. Then open `Send` and confirm its
target, publication, composer, and saved requests are untouched.

## Scenario 4 — Notes, controllers, programs (User Story 3, FR-015 … FR-021)

Send a Note On for **note 60**, a Control Change on **controller 7**, and a Program Change for
**program value 0**. Then walk the settings:

| Setting | Expect |
|---------|--------|
| `Note (Middle C = C3)` | note reads `C3` |
| `Note (Middle C = C4)` | note reads `C4` |
| `Decimal number` (note) | note reads `60` |
| `Hexadecimal number` (note) | note reads `3C` |
| `Standard name` | controller 7 shows its standard name |
| `Decimal number` (controller) | controller reads `7` |
| `1 – 128 (Standard)` | program reads `1` |
| `0 – 127 (Less common)` | program reads `0` |

Two independence checks, both required (FR-021):

- Changing `Note format` must **not** change the velocity beside the note — that is `DataFormat`.
- Changing `Controller format` must **not** change the controller's value.

Then send a Control Change on a controller with no standard name (try **85**) and confirm under
`Standard name` it is still identified by number — never blank (FR-018).

Edge check: send note **0** and note **127** and confirm both render a name under both
conventions; note 0 under `C3` reads `C-2`, which is correct (SC-004).

## Scenario 5 — Host time (User Story 4, FR-013, FR-014)

Capture a handful of events. For one event, record its `Time` cell under each of the four formats.

Expect:

- `Clock time` → `HH:MM:SS.mmm`.
- The three host forms are **consistent conversions of one another** for that same event:
  seconds × 1,000,000,000 ≈ nanoseconds, and the integer form divided by the platform tick rate
  ≈ the seconds form.
- Most important: events captured **before** you selected a host format still show host time
  (FR-025a). If they show zero or blank, the arrival reading is not being captured unconditionally.

## Scenario 6 — Expert mode (User Story 5, FR-022, FR-023)

Send a **Note On with velocity 0**.

1. Unticked: the row reads `Note Off`.
2. Tick `Expert mode`: **the same retained row**, without re-sending, now reads `Note On`.
3. Confirm data values are shown raw rather than per the settings above.
4. Untick: all three conveniences return, and the five format settings are still exactly as you
   left them — you should not have to re-choose any of them (FR-023).

Filter check (FR-027): with the `Note Off` filter checkbox unticked, confirm that ticking and
unticking `Expert mode` does **not** change which rows are listed. Display settings must never
move an event past a filter.

## Scenario 7 — Sources and Other (User Story 6, FR-005, FR-006)

Click `Sources`, then `Other`. Each must be selectable, must state its settings are not yet
available, and must offer **no operable control**. Return to `Display` and confirm every setting
is as you left it.

## Scenario 8 — Persistence (FR-028, FR-029, FR-030, SC-006)

1. Set all six settings to non-default values. Quit the application.
2. Relaunch. All six are as you left them, and the monitor renders accordingly.

Then the backward-compatibility check, which is the one most likely to be skipped and the one
with the worst failure:

3. Quit. Edit the settings store document and **delete the `display` key**, keeping the rest.
4. Relaunch. Expect the six defaults, and **every other setting intact** — filters, columns,
   retention, source selections, and the send screen's saved requests (FR-029).
5. Quit. Put an unrecognised value in **one** display field, e.g. `"time": "sundial"`.
6. Relaunch. Expect that one setting at its default, **the other five preserved**, and again
   every non-display setting intact (FR-030).

Step 6 is the sharp one: `StoreSettingsRepository::load` treats an unreadable document as absent,
so a whole-document deserialisation failure would silently wipe everything the user configured.

## Definition of Done

Beyond the gates above ([constitution](../../.specify/memory/constitution.md), Development
Workflow):

- Every new or modified public item carries rustdoc/TSDoc explaining **why**.
- Every new module carries a module-level doc naming its responsibility and its layer.
- No dead code, no unnamed magic values, no `unwrap`/`expect`/`any` outside `main`.
- IPC changes regenerated the TypeScript contract from the Rust declarations.
- The side-by-side comparison in Scenario 1 was actually performed.
- `message.rs`'s superseded middle-C-equals-C4 justification was **replaced** with FR-011a's
  reasoning, not deleted — so the next reader does not restore C4 as a bug fix.
